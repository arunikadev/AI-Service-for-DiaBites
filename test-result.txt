skala capstone tanpa ganti OCR. Yang menahan akurasi sekarang bukan "foto user
jelek", melainkan post-processing (duplikat box, parser) + cara crop ke CRNN.

     Penambahan data grayscale terbukti menambah recall deteksi baris.

D. YANG MASIH RUSAK + AKAR MASALAH
--------------------------------------------------------------------------------
D1. SALAH-BACA DIGIT = "CTC repeated-character collapse"  [PRIORITAS UTAMA]

    Pola: Energi 100 -> "10"  dan  110 -> "10". Keduanya menjatuhkan SATU digit
    kembar ("00"->"0", "11"->"1"). Ini ciri khas CTC collapse: dua karakter
    identik berurutan digabung jadi satu bila tidak ada token "blank" di antaranya.

    BUKTI EMAS (dari data 4 di atas):
        Line 4: "Energi Total 10 kkal"   (collapse -> 10)
        Line 5: "Energi Total 110 g"     (BENAR -> 110)
    Box yang sama, dua framing crop berbeda: satu collapse, satu BENAR. Artinya
    model SEBENARNYA BISA membaca 110 -- masalahnya alokasi "frame"/time-step ke
    digit, bukan kemampuan model. Saat crop lebar dengan GAP besar antara label
    dan nilai ("Energi Total ........ 100 kkal"), gap memakan time-step sehingga
    digit nilai terlalu padat -> blank antar digit kembar hilang -> collapse.

    => Ini BUKAN soal warna/resolusi. Grayscale tidak menyentuhnya. Tapi BISA
       diperbaiki (lihat F-P1).

D2. DUPLIKAT BOX MELEDAK (model grayscale lebih sensitif)
    data 4 (512px): 10 box untuk label 5-baris ("Gul g", "Gula g", "Gula S 27 g",
    Energi ganda, Gula ganda). NMS default (iou=0.7) tidak membuangnya.

D3. PARSER AMBIL MATCH PERTAMA
    data 4: Gula=0 padahal "Gula 1 g" ADA -- karena token sampah "Gul g" /
    "Gula S 27 g" cocok keyword "gula" lebih dulu, lalu tak ada angka valid.

F. ACTION ITEMS — UNTUK AI ENGINEER
--------------------------------------------------------------------------------
[P0] Cepat (post-processing, tanpa retrain — bisa hari ini)
  1. NMS lebih ketat: model.predict(..., iou=0.5). Buang ledakan duplikat.
     CATATAN: dedup harus simpan box yang baca BENAR. Karena kasus Energi
     menghasilkan "10" (conf bisa lebih tinggi) vs "110", dedup saja belum tentu
     menyelamatkan digit -> tetap butuh P1.
  2. Normalisasi resolusi: downscale gambar >~1500px ke ~1000-1200px sebelum
     pipeline. Tak memperbaiki 100->10, tapi cegah kasus 3000px hancur total.
  3. Parser tahan-duplikat: lewati token keyword yang TIDAK punya angka valid di
     dekatnya; pilih kandidat yang punya angka, bukan match pertama.

[P1] Inti akurasi digit (masih dalam skala capstone) — INI YANG PALING BERDAMPAK
  4. Perbaiki CTC collapse (lihat D1). Tiga jalur, urut dari termurah:
     a. Crop KOLOM-NILAI terpisah (hilangkan gap label<->nilai yang memakan
        time-step). Eksperimen kami: isolasi nilai membuat "100" terbaca benar.
     b. Naikkan lebar input CRNN / kurangi downsampling horizontal -> lebih
        banyak frame per digit -> blank bisa muncul antar digit kembar.
     c. Augmentasi data latih: perbanyak angka multi-digit & kembar
        (100,110,200,220,55,88,...) dengan variasi gap label-nilai.
  5. Bangun EVAL SET berlabel (30-50 foto BPOM nyata + ground-truth) lalu ukur

     apakah perubahan benar-benar menolong.

[P2] Struktural / jangka panjang
  6. Augmentasi sintetis kondisi nyata: warp perspektif (kemasan melengkung) +
     simulasi glare/brightness -> tahan foto HP asli.
  7. Pertimbangkan deteksi PER-KELAS (YOLO label tiap baris gizi sebagai class)
     -> kurangi ketergantungan pada OCR + fuzzy keyword.
  8. Bila akurasi mentok: ganti CRNN custom dengan OCR matang (PaddleOCR / Google
     ML Kit on-device). Solusi terkuat, tapi keputusan tim (saat ini ditunda).
